# 過去にハマった点

- `config.getString(path, "")` のように既定値を渡すと、jar 内 config.yml の既定値が参照されない。既定値なしで取得して null を判定すること
- plugin.yml で `default: true` にした権限でも、登録されないと Bukkit は「OP のみ」として扱う。全員向けの機能を権限で縛らない
- IntelliJ の「アーティファクトのビルド」はクラスファイルが入らないことがある。必ず Gradle でビルドする
- 乗客を `remove()` すると内部で降車イベント(`EntityDismountEvent`)が出る。これをキャンセルすると、消えた乗客が乗ったまま残り、サーバーが毎 tick 降ろそうとして重くなる(1.1.0 で発生)。1.1.9 で降車のキャンセル自体をやめた
- ゾーン内で降車をキャンセルしていたため、見た目が乗っている人はスポーン(放置ゾーン)から /tp や /home で飛べなかった。Paper は乗客が乗っている人のテレポートを失敗させ、EssentialsX などはテレポート前に乗客を降ろそうとする。降車は止めないこと(1.1.8 まで発生、1.1.9 で修正)
- 放置ゾーンの端の席で、座ったまま頭 MOB を出せなかった。WorldGuard の `mob-spawning` が deny の場所で、プラグインが出す MOB も止められていた(WorldGuard の設定で解決)。出現の失敗を何も出していなかったので、原因に気づくのに時間がかかった。失敗したら警告を出すようにした
- 統合版で、座っている人の名前が 2 つ・0 個になった(1.1.11)。統合版は座った時点の乗客の有無で名前を決めて変えないことに気づかず、本番で試しては外れた。統合版の見え方は、実際に統合版で操作ごとに確かめてから設計する
- 座る瞬間に頭の MOB を外し、次の tick に出し直す案は採らない。外した瞬間の判定では名前が出るが、あとから見えるようになった統合版の人(ログイン・接近)には、Paper が「本人の乗客(MOB)」を先に、「乗り物の情報」を後に送るので、MOB がいる状態で判定されて名前が隠れる。名前の TextDisplay も統合版の人には隠していたので、名前が 0 個になった(本番で発生)
- 統合版で出したばかりの魚が床に残る件は、後から乗せ直しても直らなかった(同じ tick に降ろして乗せると、乗客の並びが変わらないので乗車情報が送られない。tick を分けて送り直しても床のまま)。入り直すと直ることから、届くときの位置の違いと考えて、頭の高さに出すようにしたら直った。床に残る仕組みそのものは特定できていない
- 上の「頭の高さに出したら直った」は、本人がその場から動かない場合しか確かめていなかった。統合版は乗客になった魚(フグ・タラ・シャケ)を本人と一緒に動かさず、歩くと出た場所に置き去りにする(本番で、ゾーンに入った境目に魚が浮いて残った)。入り直しや出し直しで直ったように見えたのは、今の位置に描き直されただけだった。魚は乗せずに動かすようにした。見た目を確かめるときは、出したあとに歩く・座る・テレポートするところまで見る
- 統合版で、頭に鶏を乗せた人の名前が 0 個になった(1.1.12)。サーバー側では名前の TextDisplay は鶏に乗っていて、統合版の人にも見せていた。統合版の人が入ってきたときや、近づいてきたときに見え始めると出ず、reload などでその場で作り直すと出るので、直ったように見えてしまった。調べるときは、統合版でリログしたあとの見え方を何回か確かめる。鶏の上に文字のない TextDisplay を挟んで 2 段にしたら出るようになった。名前を本人に乗せる案は、リログすると 0 個になったので採らない
- 停止中(`onDisable`)は `hidePlayer`・`hideEntity` が「Plugin cannot be disabled」の例外になる。1.1.12 では、後片付けの途中で座っている人を統合版の人に出し直そうとして例外になり、見た目の削除の残り・`cosmetics.yml` と `config.yml` の保存・スコアボードを戻す処理・保存スレッドの停止が飛んだ(PlugManX の reload で発生)。停止中は出し直さない
- 統合版で、本人を `hidePlayer` → `showPlayer` で出し直すと、スキンが外れて Steve になることがあった(1.1.12)。タブリストから一度消えるためと考えられる。座っている人は座席を出し直す方式に変えた。統合版の見え方は、プレイヤーごとの状態をサーバー側で記録しながら、同じ操作を何回か繰り返して確かめる(1 回だけの結果で判断して何度も外した)
- 統合版で、立っていて頭に MOB がいる人の名前が 0 個になった(1.1.12)。最初はカエルの人だけで見つかったのでカエル特有と考えたが、全種類を 15 秒ずつ付け替えて確かめると、どの MOB でも見え始めの約 5〜8 秒後に本人の名前が消えていた。2 秒ずつの付け替えでは消える前に次へ進むので、気づけなかった。MOB の種類ごとの違いを調べるときは、症状が出るまでの時間より長く待つ
- 1.1.13 で、立っていて頭に MOB がいる放置中の人の名前が、統合版から 2 つになった。上の「約 5〜8 秒後に消える」は時間で消えていたのではなく、試した人が動く間にスニークやダッシュをして、統合版が本人の名前を決め直していた。放置中の人は何もしないので、本人の名前が出たままだった。歩いたら直った・席から立ったら出た、と思い込んで何度も外したが、本当に効いていたのはスニーク(手順の途中に入れたスニークで気づいた)。統合版の見え方を調べるときは、試した操作のほかに、スニーク・ダッシュ・ジャンプなどをしなかったかも記録する。サーバーからスニークを 1 tick だけ変えて戻すと決め直させられる
- 統合版で、座ったまま頭の MOB が変わると、名前が 2 つ(次が魚なら 0 個)になることがあった(1.1.14 まで)。座席の出し直しを、乗客を変えたのと同じ tick に呼んでいたため。Paper は乗客の変化を tick の最後に送るので、出し直しのほうが先に届き、統合版は変わる前の乗客で名前を決めていた。出し直しと 3 tick ごとのタスクのずれで 3 回に 1 回だけ起き、少し試しただけでは出なかった(MOB の種類のせいに見えた)。全種類を 5 秒ごとに付け替え、tick ごとの順番をログに出して気づいた。乗客を変えたあとの出し直しは次の tick にする。タイミングが怪しいときは、同じ操作を周期を変えて何度も繰り返して、起きた回に規則がないかを見る
- 統合版で、座ったまま頭の MOB を外して(魚に変わった・非表示にした)立った人のスキンが、リログするまでスティーブになった(1.1.15)。立ったときに本人を出し直す処理が、座ったまま座席を出し直して名前を決め直させたあとでも動いていた。本人の出し直しは毎回スキンを読み込み直させ(一瞬スティーブになる)、まれに読み込みが失敗したままになる。10 回試して長く続くものは出なかったので、1 回試して出ないだけでは原因から外さない。本人の出し直しは、要らない場面で呼ばない
- 統合版だけ、サイドバーがちらついた(初版から 1.1.16 まで)。5 秒ごとに全行を `resetScores` してから書き直していたため。Java 版は同じ tick の処理なので見えず、Geyser は行の削除をそのまま送るので一瞬空になる。サイドバーは変わった行だけ書き換える
