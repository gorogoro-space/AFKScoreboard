# 過去にハマった点

- `config.getString(path, "")` のように既定値を渡すと、jar 内 config.yml の既定値が参照されない。既定値なしで取得して null を判定すること
- plugin.yml で `default: true` にした権限でも、登録されないと Bukkit は「OP のみ」として扱う。全員向けの機能を権限で縛らない
- IntelliJ の「アーティファクトのビルド」はクラスファイルが入らないことがある。必ず Gradle でビルドする
- 乗客を `remove()` すると内部で降車イベント(`EntityDismountEvent`)が出る。これをキャンセルすると、消えた乗客が乗ったまま残り、サーバーが毎 tick 降ろそうとして重くなる(1.1.0 で発生)。1.1.9 で降車のキャンセル自体をやめた
- ゾーン内で降車をキャンセルしていたため、見た目が乗っている人はスポーン(放置ゾーン)から /tp や /home で飛べなかった。Paper は乗客が乗っている人のテレポートを失敗させ、EssentialsX などはテレポート前に乗客を降ろそうとする。降車は止めないこと(1.1.8 まで発生、1.1.9 で修正)
- 放置ゾーンの端の席で、座ったまま頭 MOB を出せなかった。WorldGuard の `mob-spawning` が deny の場所で、プラグインが出す MOB も止められていた(WorldGuard の設定で解決)。出現の失敗を何も出していなかったので、原因に気づくのに時間がかかった。失敗したら警告を出すようにした
- 統合版で、座っている人の名前が 2 つ・0 個になった(1.1.11)。統合版は座った時点の乗客の有無で名前を決めて変えないことに気づかず、本番で試しては外れた。統合版の見え方は、実際に統合版で操作ごとに確かめてから設計する
- 座る瞬間に頭の MOB を外し、次の tick に出し直す案は採らない。外した瞬間の判定では名前が出るが、あとから見えるようになった統合版の人(ログイン・接近)には、Paper が「本人の乗客(MOB)」を先に、「乗り物の情報」を後に送るので、MOB がいる状態で判定されて名前が隠れる。名前の TextDisplay も統合版の人には隠していたので、名前が 0 個になった(本番で発生)
- 統合版で出したばかりの魚が床に残る件は、後から乗せ直しても直らなかった(同じ tick に降ろして乗せると、乗客の並びが変わらないので乗車情報が送られない。tick を分けて送り直しても床のまま)。入り直すと直ることから、届くときの位置の違いと考えて、頭の高さに出すようにしたら直った。床に残る仕組みそのものは特定できていない
