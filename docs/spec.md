# 機能仕様

(現在の実装の動作。仕様を変えたらここを更新する)

- **ゾーンの読み込み**: 起動時に AxAFKZone の `zones/*.yml` から `zone.location1` / `zone.location2` を読み取り、直方体の範囲(各辺 ±0.5 拡張)として保持する。AxAFKZone は softdepend
- **ボードの表示**: ゾーン内にいるプレイヤーにサイドバー「放置時間ランキング」を表示し、ゾーン外に出たらメインスコアボードに戻す。出入りの判定は PlayerMoveEvent(ブロックの X/Z が変わったときのみ)、ログイン時、プラグイン起動時に行う
- **連続放置時間**: ゾーン内のプレイヤーを 1 秒ごと(20 tick のタスク)に +1 秒する。ゾーン外に出るとリセット
- **ランキング**: 5 秒ごと(100 tick のタスク)に、今ゾーンにいる人を今週の累計で上位 10 人まで表示する。右側の数字は非表示。行は毎回作り直すが、サイドバーへは差分だけを反映する(`applyBoardLines`。要らなくなった行だけ `resetScores` し、無い行とスコアが違う行だけ `setScore`)。全行を消してから書き直すと、統合版(Geyser)では一瞬サイドバーが空になり、更新のたびにちらついた(1.1.16 まで)
- **週間累計**: ゾーン内の秒数を 1 秒タスクで `data.yml` に足す。`/afkhide` 中も続く。ゾーンを出ても、ログアウトしても、再起動しても残る。週の区切りは `timezone`(既定 Asia/Tokyo)の `week-start-day`(既定 MONDAY)00:00。保存は 60 秒ごとと停止時に、専用スレッド `AFKScoreboard-Weekly`
- **回線落ち救済**: ゾーン内でログアウトし、5 分以内に再ログインしてゾーンに入れば時間を引き継ぐ(メモリ上のみ。サーバー再起動や PlugManX での再読み込みで消える)
- **`/afkhide`**: ランキングへの表示/非表示を切り替える。非表示中は連続放置をカウントしない。週間累計は続く。ゾーン内ではボード自体は表示する。見た目ボーナスは付けない(切り替えた時点で外す・付け直す。見た目用の今週の秒数は数え続ける)。権限なし(全員が使える)
- **スペクテイター・バニッシュ中**: `GameMode.SPECTATOR` か、メタデータ `vanished` の値が true(EssentialsX は解除時に false を入れるので、有無ではなく値で見る。softdepend は付けない)の人は、`isConcealed` で判定し、ランキングに載せず、見た目も付けず、本人のボードも出さない(放置ランキングのボードならメインに戻す)。連続放置・週間累計・見た目用の秒数は数え続ける。抽選結果と `/afklook` は残す。新しいイベントやタスクは増やさず、ゾーン内での切り替えは既存の 1 秒タスクで反映する(ボードを外した人を `concealedPlayers` に覚え、戻ったらその人だけボードを付け直す。他プラグインのボードは上書きしない)。連続放置のカウント条件は「ゾーン内で `/afkhide` していない」(ボードの有無は見ない)
- **`/afkdebug`**: OP 専用（`afkscoreboard.debug`、plugin.yml のコマンドに permission を付ける）。`particle`（30分）/ `block`（1時間）/ `mount`（3時間）/ `all`。未抽選の枠だけその場で決め、放置秒数は増やさない。ゾーン内なら即表示し、ゾーン外なら入域時に出す
- **`/afklook`**: 権限なし(全員が使える)。`particle` / `block` / `mount` / `all` で見た目を種類ごとに表示/非表示に切り替える(`all` は 1 つでも表示中なら全部 OFF、全部 OFF なら全部 ON)。OFF の種類は抽選結果と秒数を残したまま付けない(引き直しにならない)。`cosmetics.yml` の `look-off` に保存し、週のリセットでは消さない。`reset` は見た目の抽選結果をすべて外し秒数は残すので、条件を満たしている枠は 1 秒後に引き直される(引き直しとして許容)
- **初回案内**: 初めてゾーンに入ったときに `/afkhide` の案内を一度だけ表示する
- **保存データ**: `config.yml` の `hidden-players`(非表示中)と `welcomed-players`(案内済み)に UUID のリストとして保存する。見た目の秒数と抽選は `cosmetics.yml`(`/afklook` の OFF は同じファイルの `look-off`、週をまたいで残る)
  - 保存のタイミングは変更時(`/afkhide` 実行時、初回案内時)とプラグイン停止時
  - `getConfig()` の更新と YAML 文字列への変換はメインスレッドで行い、ファイルへの書き込みだけを専用スレッド(1 本)で行う。書き込み待ちが残っている間の変更は、最新の内容で 1 回にまとめて書き込む
  - プラグイン停止時は、書き込み待ちが終わるまで最大 10 秒待つ
  - `cosmetics.yml` も同じ形で、別スレッド `AFKScoreboard-Cosmetic` に書く。`onDisable` ではその前にパーティクル以外の見た目エンティティを消す

## 見た目ボーナス

### 基本
- ゾーン内にいる秒数だけを 1 秒タスクで数える。30 分でパーティクル(既定 60 tick = 3 秒に 1 回、1〜2 粒)、1 時間で BlockDisplay、3 時間で静かな頭 MOB(ネームタグが隠れるので、名前の TextDisplay を MOB に乗せて表示する。統合版の人にだけ隠せるよう、MOB の customName は使わない。ラクダ・クリーパーだけは customName)。世界のブロックは置かない。乗客なので毎 tick のテレポートはしない(魚だけは例外、下記)。
- 頭 MOB はプレイヤーの頭の高さ(位置+`getHeight()`)に出してから乗せる(足元に出すと、統合版で魚が頭に乗らず床に残った)。
- 魚(フグ 2 種・タラ・シャケ。`org.bukkit.entity.Fish`、`follows`)は乗せない。統合版は、乗客になった魚を本人と一緒に動かさず、出た場所(頭の高さ)に置き去りにする(リログや `hideEntity` → `showEntity` では今の位置に描き直されるだけで、歩くとまた残る。イカは付いてくる。Geyser のソースでは乗車の扱いは全 MOB 同じで、魚だけ違うのは泳ぐ・呼吸などの印だけ)。代わりに、既存の `onPlayerMove`(`syncMount`)で本人の位置か向きが変わったときと、座っている間は `tickSeated`(3 tick)で、頭の高さへテレポートする(`followHead`。同じ位置と向きなら何もしない)。Java 版からは少し遅れて付いてくる(テレポートした MOB の補間。毎 tick 動かしても同じだった)。テレポートしたときは次の tick に頭へ動かし、別のワールドなら消して 1 秒タスクで出し直す。`sync` は、魚が乗っているかではなく、本人と同じワールドにいるかを見る。
- 抽選は週が変わるまで固定で `cosmetics.yml` に保存する。
- 頭 MOB の出現を他のプラグインに止められたら(`isValid()` が false)、警告は失敗が続く間の最初の 1 回だけ出す(`mountSpawnFailed`)。
- ゾーン外・ログアウト・死亡・`onDisable` で乗客を remove する。乗客の降車(`EntityDismountEvent`)は止めない(テレポートの前に他プラグインが乗客を降ろすため。止めると /tp や /home で飛べなくなる)。降りた見た目は 1 秒タスクの `sync` が乗せ直し、ゾーン外なら片付ける。
- 起動時にも、前回残った自前エンティティ(PDC `cosmetic`)をロード済みの範囲から消す。
- エンダードラゴンは出さない。`PlayerMoveEvent` は増やさない。

### 頭の MOB の向きと、座っている間
- 頭 MOB の向き(左右・上下)は、既存の `onPlayerMove` で向きが変わったときだけ `setRotation` で合わせる(位置は動かさない。MOB がいない人は Map を引いて抜ける)。
- ヤギだけは `setYHeadRot` が体から ±15° に頭を固定するため、`setRotation` の前に `setBodyYaw` で体を同じヨーにする。これをしないと頭の回転が振り向きまで届かず、立ち止まって見ているあいだ体が止まったままになる。
- 乗り物に乗っている間(GSit で座っているなど)は PlayerMoveEvent が来ないので、3 tick ごとのタスク(`tickSeated`)で、頭上に MOB がいて乗っている人だけ合わせる。
- 同じタスクで、足元のブロック(花びらと、キノコと枯れ木の地面側だけ)は乗っている間だけ 0.75 上(座面の高さ)に上げる。体から生えている分は上げない。切り替えるのは座った・立ったときだけ。

### ブロックの種類と配置
- ブロックはクモの巣・ツツジ・花びら・苔カーペット・苔ブロック・ツタ・茶キノコ・赤キノコ・枯れ木・ペールの垂れ苔・ペールオークの葉の 11 種類(落ち葉はほとんど見えないので削除。保存済みの値は読めないので自動で引き直される。キノコは `BROWN_MUSHROOM` / `RED_MUSHROOM` で、キノコブロックではない)。
- ツタは胴・肩・脚に沿った薄い面(表裏の 2 面だけ)で、体に絡んだように置く。
- 苔カーペット・苔ブロック・開花したツツジの葉は肩・背中・胴から生えた配置で、足元の敷物にはしない。
- 茶キノコと赤キノコは体からと足元の複数本。枯れ木も体と足元で、上がるのは足元だけ。
- ペールの垂れ苔は先端の房を胴の横・背中・肩・脚に垂らす。ペールオークの葉はツツジと同じ位置。
- 目の正面は空ける。

### 頭の MOB の種類・大きさ・MOB ごとの対策
- 頭 MOB は猫・蛙・フグ(最大膨張)・フグ(半膨張)・鶏・兎(大人)・狐・蜂・オウム・子牛・子シロクマ・村人の子供・狼・亀・ウーパールーパー・タラ・シャケ・ムーシュルームの子供・イカ・ヒカリイカ・アルマジロ・オウムガイ・ゾンビオウムガイ・スニッファー・ラクダ・子ヤギ・子豚・子ヒツジ・パンダ(大人)・スライム・クリーパー(レア枠として 1％の確率で抽選)。
- スニッファーとラクダは `Attribute.SCALE` 0.35、パンダは 0.45、亀は 0.5、スライムは `setSize(2)` のあと 0.55、オウムガイとゾンビオウムガイは 0.65、イカとヒカリイカは 0.7、狼は 0.75、クリーパーは 0.5。半膨張のフグは縮めない。ムーシュルームとヤギと豚と羊は `setBaby`。
- クリーパーは爆発半径 0 で、着火・帯電・爆発はキャンセルする。
- ラクダ・オウムガイ・ゾンビオウムガイに他人が乗るのは `EntityMountEvent` で止め、ムーシュルームの毛刈りは `PlayerShearEntityEvent` で止める。
- 鶏の卵は `EntityDropItemEvent` で止める(`setEggLayTime` だけでは産んでしまい、乗せている人のインベントリが卵で埋まった。種類が鶏でなければすぐ抜ける)。
- 自前の MOB が燃えるのは `EntityCombustEvent` で止める(ゾンビオウムガイが日光で燃えた)。
- 自前の MOB が別の MOB に変わるのは `EntityTransformEvent` と `EntityZapEvent`(雷での変身。HandlerList が別)で止める(雷で豚・村人が変身し、自前の印のない MOB が残った。止めても一度降ろされるので、約 10 秒消えて戻る)。
- ムーシュルームは雷で色が入れ替わり、止めるイベントが無いので、1 秒タスクの `sync` で抽選した色に戻す。

### 名前の TextDisplay
- 何かが乗っているプレイヤーのネームタグは Java 版のクライアントが表示しないため、ブロックか頭 MOB がある間は、名前の TextDisplay(`player.displayName()`、Billboard CENTER)を乗客として出す。
- 頭 MOB がいれば MOB に、いなければプレイヤーに乗せる(MOB が出た・消えたら乗せ替える。自前同士の乗車は `EntityMountEvent` で止めない)。本人には `hideEntity` で見せない。
- 頭が魚の人は、名前をプレイヤーに乗せ、高さを 0.25 に魚の高さ(`getHeight()`)を足した分にする(魚に隠れないように)。高さが変わったら作り直す(`Active.nameTagLift`)。
- 頭 MOB が鶏のときだけ、鶏の上に文字のない TextDisplay(`Active.spacer`)を乗せ、名前はその上に乗せる(高さ `CHICKEN_NAME_TAG_LIFT` = 0.6。ほかは 0.25)。2 つとも最初から鶏の位置に出す(足元に出すと、乗るまでの一瞬だけ床に名前が見える)。鶏とそれ以外が入れ替わったら、高さが違うので名前を作り直す。Floodgate の有無に関係なく常にこうする。
  - 理由: 鶏に直接乗せると、統合版の人があとから見始めたとき(ログイン・接近)に名前が出なかった(サーバー側では名前は鶏に乗っていて、統合版の人にも見せていた)。Geyser は乗り物が鶏のとき乗客の位置を別に計算し、名前の高さ(translation)は乗り物が TextDisplay かプレイヤーのときしか使わない。2 段にすると、本番でリログ 3 回とも表示された。
- 頭 MOB がラクダ・クリーパーのときは、名前の TextDisplay を出さず、MOB 自体に `customName`(`player.displayName()`)を付けて見せる(`syncMobName`。透明な間は外す)。Java 版は乗客のいない MOB の名前を出すので 1 つになる。Floodgate の有無に関係なく常にこうする。
  - 理由: ラクダ・クリーパーの上に乗せた名前の TextDisplay は、統合版で表示されなかった(座っていても立っていても。鶏と同じ 2 段にしても出ない)。名前を本人に乗せる方式でも統合版では出たが、Java 版で名前が MOB の体に隠れるおそれがあるので採らなかった。
- 出す・外すは 1 秒タスクの `sync` で判定し、後片付けはブロックと同じ。
- プレイヤーが透明な間(`player.isInvisible()`。GSit の `/lay` は本物のプレイヤーを透明にし、名前付きの寝姿を別に出すため、名前が二重になる)は名前の TextDisplay を出さない。MOB 本体は残す。

### 統合版
Floodgate があるときだけ。`BedrockPlayers` が Floodgate API で判定し、無ければ null で何もしない。softdepend。

- 統合版は、乗客がいても乗り物に乗っていない人には本人の名前を出す。乗り物に乗った情報(Geyser の SetEntityLink)を受け取った時点で頭に乗客がいれば本人の名前を隠し、次にその情報を受け取るまで判定を変えない(Geyser ではなくクライアントの挙動)。
- Geyser は BlockDisplay を送らないので、ブロックだけの人は統合版から見ると乗客がいない。
- 立っている人の本人の名前は、本人の状態(スニークなど)が変わったときにも、その時点の頭の乗客の有無で決め直す。見ている人ごとに決め、見え始めたばかりの人には出す。歩く・テレポート・MOB の付け替え(外して付け直しても)では決め直さない。ダッシュの状態を変えても決め直さない(本番で確認)。
  - そのため、MOB なしで座って立ったあとに MOB が付いた人や、統合版の人が後から見始めた人は、本人の名前が出たままになり、名前の TextDisplay と合わせて 2 つになった(1.1.13)。1.1.12 の調査で「見え始めの約 5〜8 秒後に隠れる」と見えたのは、試した人が動いている間にスニークやダッシュをしたためと考えられる。
- そこで、立っていて頭 MOB がいる人は、本人のスニークを 1 tick だけ変えて戻し(`pulseSneak`)、統合版に本人の名前を隠させる。MOB を出したとき(`sync`。抽選・付け替え・再読み込み直後)は 1 tick 後に行う。1 tick なので、Java 版からも統合版からもしゃがんだようには見えない(本番で確認)。停止時に戻す前なら `shutdown` で戻す。
- そこで統合版の人には、頭 MOB がいる間(座っていても立っていても)は名前の TextDisplay を `showEntity` で見せ、ブロックだけのときは `hideEntity` で隠す。切り替えは値が変わったときだけで、TextDisplay を出したとき・`sync`・`tickSeated`(3 tick、頭 MOB がいる人だけ)で判定する。統合版の人のログイン時(`onViewerJoin`)は、隠す側の名前をその人から隠す。
- 統合版の人が、立っている人の頭 MOB を後から見始めたとき(ログイン・接近)は、本人の名前が出ているので、`onTrack` の `delayNameTag` でその人にだけ名前の TextDisplay を隠し、`STANDING_NAME_DELAY_TICKS`(10 tick = 0.5 秒)後に `pulseSneak` してから見せる。出たばかりの MOB(20 tick 未満。付け替えなど)は、出したときに `pulseSneak` するので何もしない。自分の MOB を自分で見始めたとき(ログイン直後など)も何もしない。
  - ラクダ・クリーパーは名前の TextDisplay が無い(MOB の名前)ので、隠さずに 10 tick 後に `pulseSneak` だけする。1.1.14 ではこれをしておらず、統合版の人が見始めると本人の名前と MOB の名前で 2 つになった(本番で、リログ 2 回とも 1 つになるのを確認)。
- 頭が魚の人は、統合版から見ると乗客がいない(魚は乗っていない。名前の TextDisplay は隠すので届かない)ので、ブロックだけの人と同じく名前の TextDisplay を隠し、本人の名前で 1 つにする。統合版向けの判定(`syncSeatedRider`・`seatedWithRider`・`onSeat`・`syncBedrockView`)では、魚は「頭 MOB なし」として扱う(`riding`)。魚を出したときも、前の MOB で隠れた本人の名前を出させるために `pulseSneak` する。魚は乗客でないので `onTrack` では何もしない。
- 出し直しは、座っていれば乗り物(GSit の座席など)を `hideEntity` → `showEntity` する。本人を `hidePlayer` → `showPlayer` すると、タブリストから一度消えて統合版でスキンが外れる(スティーブになる)ことがあった(本番で、出し直した人だけがスティーブになり、座席を出し直す方式ではリログ 6 回とも普通だった)。乗り物を出し直しても、乗り物の情報が今の乗客の状態で届き、判定がやり直される(Paper は出し直すとき、本人の乗客を先に、乗り物の情報を後に送る)。
- 統合版は、乗客がいるまま乗り物に乗った人の本人の名前を、降りても隠したままにする。頭 MOB がいれば名前の TextDisplay を見せるのでそのままでよい。`tickSeated` で頭 MOB を乗せて乗っている人を `seatedWithRider` に覚え、降りたときに MOB がいなくなっていれば、統合版の人にだけ本人を出し直す(座席がないので本人。一瞬ちらつく)。座ったまま MOB がいなくなった(魚に変わった・非表示にした・見た目を全部外した)人は、下の (1) で座席を出し直した時点で統合版が本人の名前を出しているので、`seatedWithRider` から外し、降りても出し直さない(本人の出し直しで、統合版でスキンが外れたままになることがあった。1.1.15 まで)。
- 座ったままの判定のずれも同じ出し直しで直す。
  - (1) 座ったまま頭 MOB が出た・消えたとき: `Active.seatedRider`(統合版が判定したときに MOB がいたか。座った瞬間の `onSeat`(`EntityMountEvent`、MONITOR)で記録し、座っていなければ null)と今の有無が違えば、`tickSeated` の `syncSeatedRider` で統合版の人全員に出し直す。null で MOB がいれば(PlugManX での再読み込み直後など)判定がわからないので出し直す。座ったまま見た目を全部外したとき(`clear`)も出し直す。これをしないと、外したあとは名前が 0 個、出し直したあとは 2 個になった。どちらも、出し直すのは乗客を変えた次の tick(`resendSeatedLater`。そのときまだ座っていれば)。Paper は乗客の変化を tick の最後に送るので、同じ tick に出し直すと、統合版は変わる前の乗客で判定する(MOB が出たときは本人の名前が出て 2 個、前の MOB を消したときは隠れて、次が魚だと 0 個になった。1.1.14 まで)。
  - (2) 統合版の人が、座っていて MOB がいる人の MOB を後から見始めたとき(ログイン・接近): MOB が乗り物の情報より後に届いて本人の名前が出るので、`PlayerTrackEntityEvent`(MONITOR)で次の tick にその人にだけ出し直す。

### テレポート
Paper は乗客がいるプレイヤーの別ワールドへのテレポートを `CraftPlayer.teleport0` で失敗させ、その判定は `PlayerTeleportEvent` より前にある。

- (1) 他のプラグインが自前の乗客を降ろしたとき(`EntityDismountEvent`。自分で外すときは `removeQuietly` / `selfDismounting` で区別する)は、`pausedUntil` に入れて 1 秒タスクで付け直さない。`PlayerTeleportEvent` で解除し、最長 200 tick。Multiverse(`passenger-mode: dismount_passengers`)や EssentialsX は、降ろしてからチャンクを読み込んでテレポートするので、その間に乗せ直すと失敗した。降ろされた見た目はその場に残るので、次の tick にその人の見た目をすべて消す(`dismountClearPending` で 1 人 1 回。イベントの中で消すとまた降車イベントが出る。EssentialsX は降ろした同じ tick にテレポートし待ちが解除されるので、待ちの有無は見ない)。
- (2) 乗客を降ろさずにテレポートするコマンドは、config.yml の `teleport-commands`(起動時に読む。既定は CoreProtect の `co`・`core`・`coreprotect` の `teleport`・`tp`)に一致したときだけ、`PlayerCommandPreprocessEvent` で見た目を外し、10 tick 後に付け直す。前方一致で、「プラグイン名:」は取る。どのコマンドでも外す案は、普通のコマンドで見た目が消えるのでやめた。
- Multiverse-Portals のポータルは乗客を降ろさないので防げない(放置ゾーンにポータルを置かない運用)。
